# «Банки с вареньем» — план по этапам

Каждый этап принимается отдельно: `npm test` зелёный, `npm run build` без ошибок, в консоли браузера нет ошибок.
В скобках указаны скиллы из `.claude/skills`, по которым делается этап.

## Этап 1. Логика ✅ (puzzle, procedural-gen)

- `src/game/rng.js` — свой детерминированный генератор (mulberry32); первые значения закреплены тестом.
- `src/game/board.js` — поле, правила переливания, победа, «секретные» слои, полезные ходы.
- `src/game/session.js` — партия: ход, отмена (снимки поля), «Ещё банка» (не больше 2), «Заново», тупик, подсказка.
- `src/game/solver.js` — поиск в глубину с запоминанием состояний и лимитом; проверка «решается за ≤ N ходов».
- `src/game/generator.js` — `generateLevel(n)` по кривой сложности, секретные, сложные уровни и уровни-передышки.
- Тесты: уровни 1–500 решаемы (решение проигрывается обычными правилами), генерация < 200 мс,
  нет тривиальных, отмена ×1000 с секретными слоями, детерминизм.
- `npm run levels:report [от] [до]` — таблица уровней: сорта, длина решения, время.

## Этап 2. Игровой экран ✅ (game-ui-ux, input-systems, game-feel)

- Банки и слои — SVG; у каждого сорта цвет и значок ягоды (различимо при дальтонизме).
- Раскладка: 1–2 ряда, до 16 банок (14 + 2 добавленные) на ширине 320 px без обрезки.
- Ввод: нажатие выбирает (банка приподнимается), второе — переливает; очередь ходов —
  быстрые нажатия во время анимации применяются по порядку, без потерь и дублей.
- Анимация 350–450 мс: наклон, струя, рост слоя; покачивание при недопустимом ходе; крышка с этикеткой.
- Кнопки «Отменить», «Ещё банка», «Заново» со счётчиками; окно «Ходов нет».
- Обучение на уровнях 1–2: рука-указатель показывает ход решателя, без текста.
- Проверка: `node scripts/smoke.js` (при запущенном `npm run dev`) — Chrome на 320/360/390/480 px,
  16 банок без обрезки, прохождение уровней 1, 35, 90 быстрыми нажатиями, ошибки консоли.
- Для проверки любого уровня: `http://localhost:5173/?level=35`.

## Этап 3. Обвязка ✅ (save-systems, audio-design, game-ui-ux)

- `common/`: `storage.js` (schemaVersion, миграции, запись в платформу и localStorage, выбор по версии),
  `audio.js` (звуки синтезом WebAudio — без чужих файлов; выключатель; пауза при сворачивании),
  `ui.js` (окна, кнопки, тосты), `analytics.js` (очередь событий).
- Экраны: главный, победа (полка с закатанными банками), кладовая (полка или украшение каждые 10 уровней), настройки.
- Ежедневный подарок: лента на 7 дней, пропуск сбрасывает. Монеты: 10 / 20 за сложный; 50 монет = 5 отмен.
- `data/strings.json` — все тексты.
- Сделано: `game/progress.js` (схема 1, миграция со временного сохранения этапа 2, экономика, кладовая),
  `common/daily.js` (лента подарков, защита от перевода часов назад), `common/storage.js`
  (запись на устройство сразу, на платформу — с задержкой 0,8 с и при сворачивании), звук синтезом,
  окно «5 отмен за 50 монет», в кладовой — банка за каждый уровень, полка за 10 уровней, украшение за 20.
- Подсказка за 30 монет (`ECONOMY.hintCost`): рука показывает следующий ход по решателю; если выхода нет — монеты не списываются.
  «Заново» перенесено значком в шапку, внизу три кнопки: «Отменить», «Ещё банка», «Подсказка».
- `node scripts/smoke.js` теперь проходит путь «подарок → уровень 1 → победа → перезапуск» и проверяет сохранение.

## Графика (между этапами 3 и 4) ✅ (create-game-assets, game-feel)

- Банки — SVG (`screens/jarArt.js`): толстое стекло с бликами, варенье с объёмом и кусочками ягод,
  глянцевая поверхность, крышка из ткани в клетку с бечёвкой, этикетка-значок. Значок сорта на каждом слое остался.
- Переливание — Canvas (`screens/pourFx.js`): поверхность варенья горизонтальна при любом наклоне (объём слоёв сохраняется),
  банка наклоняется вокруг края горлышка, струя дугой, волна в получателе, брызги, искры над собранной банкой.
- Кухня: обои в мелкий цветочек, свет из окна, деревянные полки с волокнами.
- `node scripts/perf.js` — 60 к/с при процессоре, замедленном в 6 раз. `?slowmo=10` — переливание в замедлении для проверки.

## Этап 4. Монетизация ✅

- `common/platform.js`: VK Bridge и локальная заглушка «Реклама (тест)» на 2 с, покупки — мгновенный успех.
- Rewarded: +5 отмен, +1 банка, удвоение монет; при недоступной рекламе награда не выдаётся.
- Interstitial: с 4-го уровня, не чаще раза в 3 минуты, только между уровнями; «Без рекламы» отключает его.
- `data/shop.json`, отдельный экран магазина; `server/payments.js` — HTTP-обработчик уведомлений VK
  с проверкой подписи, товара и цены, разделением тестовых и боевых заказов, идемпотентными ответами.

## Этап 5. Платформа (код готов; осталась проверка внутри VK и ОК)

- Подключён VK Bridge 3.0.2; методы и типы ответов сверены с установленным пакетом VK.
- Добавлены legacy-сборка и полифиллы для старых браузеров, `LICENSES.md`, команды проверки и инструкция деплоя.
- Локально пройдены unit-тесты, production-сборка, полный сценарий из 10 уровней и все точки монетизации.
- Перед публикацией обязательны реальные проверки VK и ОК на телефоне: инициализация, облачные сохранения,
  показ rewarded/interstitial, отказ от рекламы, тестовая покупка и повторный запуск.

## Отступление от ТЗ (этап 1)

Генератор делает не K обратных переливаний, а K обменов слоями между банками из решённого состояния,
и затем, как в ТЗ, проверяет решателем решаемость и отбраковывает тривиальные уровни.
Причина измерена: обратный обход приходил к стартовой форме «все банки полные + 2 пустые» лишь в ~20% случаев,
и поля были почти не перемешаны (12 сортов: ~14 пар одинаковых соседних слоёв из 36 против ~2 у случайного поля),
то есть уровни получались слишком лёгкими. Обмены сохраняют форму поля, а K — удобная ручка сложности.
